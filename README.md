# 1001 Dates

MVP веб-приложения, которое собирает **3 готовых сценария свидания** по времени, бюджету, настроению, району и способу передвижения. После выбора сценария создаётся открытка-приглашение.

## Что уже работает

- 3 разных сценария вместо каталога мест;
- фильтры: дата, старт, длительность, бюджет, настроение, район, транспорт;
- режимы «нужна еда», «только помещение», «учитывать события»;
- оценка дороги от выбранной зоны, между точками и обратно домой;
- жёсткий контроль общего окна времени «вышел → вернулся»;
- контроль ориентировочного бюджета;
- события как якорь маршрута;
- генерация приглашения и Web Share / копирование;
- mobile-first адаптивный интерфейс;
- PWA manifest + service worker;
- seed-база Москвы и автоматический импорт KudaGo.

## Самый простой запуск

Никаких npm-зависимостей нет.

```bash
python3 -m http.server 8080
```

Откройте `http://localhost:8080`.

> Не открывайте `index.html` двойным кликом: ES modules и service worker рассчитаны на HTTP(S).

## Обновить базу

Скрипт использует публичный KudaGo API и Node.js 18+:

```bash
node scripts/update-kudago.mjs
```

По умолчанию загружаются до 300 популярных мест Москвы и до 200 актуальных событий, затем остаются только категории, пригодные для сценариев свиданий. Результат записывается в `data/kudago.generated.js`.

Можно изменить объём:

```bash
KUDAGO_PLACE_PAGES=5 KUDAGO_EVENT_PAGES=4 node scripts/update-kudago.mjs
```

## Залить на GitHub Pages

1. Создайте публичный репозиторий, например `1001-dates`.
2. Загрузите содержимое этой папки в корень репозитория.
3. GitHub → **Settings → Pages**.
4. В **Build and deployment** выберите **Deploy from a branch**.
5. Branch: `main`, folder: `/ (root)`.
6. Сохраните настройки.

Все ссылки в приложении относительные, поэтому оно работает и на `username.github.io/1001-dates/` без изменения `base`.

Workflow `.github/workflows/refresh-data.yml` раз в сутки обновляет KudaGo snapshot и коммитит изменения. Для ручного обновления откройте **Actions → Refresh KudaGo data → Run workflow**.

## Данные

В `data/seed.js` лежит небольшой fallback-набор реальных московских мест и событий, чтобы приложение работало сразу и не зависело от внешнего API в браузере. Цены с `costEstimated: true` — **оценки для планирования**, а не обещанная стоимость.

`data/kudago.generated.js` заполняется официальным публичным KudaGo API. Данные обновляются серверным/CI-скриптом, а не запросами из браузера: так страница остаётся быстрой и предсказуемой.

## Архитектура

```text
index.html / styles.css
        ↓
      app.js               UI + invitation
        ↓
     engine.js             planning / scoring / timing
        ↓
seed.js + kudago.generated.js
        ↑
scripts/update-kudago.mjs  data ingestion
```

Planning engine не зависит от DOM. При переносе в React/React Native/Flutter его можно заменить или вынести в API без изменения модели данных.

## Что делать перед реальным запуском

1. Добавить точную маршрутизацию через Google Routes / Яндекс Маршрутизацию вместо зональной оценки.
2. Добавить бронирования и проверку availability.
3. Вынести данные и профили пар в PostgreSQL/Supabase.
4. Добавить авторизацию и сохранённые свидания.
5. Добавить feedback loop после свидания для персонального ranking.
6. Добавить серверную генерацию share-card / OG image.
7. Перед коммерческим запуском перенести hosting с GitHub Pages на обычный production hosting/backend.

## Принцип продукта

`constraints → candidates → feasibility → scoring → 3 diverse dates → invitation`
