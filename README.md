# 1001 Dates

**1001 Dates** — веб-приложение, которое предлагает три готовых сценария свидания по выбранным ограничениям.

Главный принцип интерфейса: минимум действий до результата. Пользователь выбирает:

- где;
- когда;
- сколько времени есть на свидание;
- бюджет на двоих;
- настроение;
- при необходимости — несколько дополнительных пожеланий.

После этого приложение показывает ровно три цельных сценария и позволяет превратить выбранный вариант в приглашение.

## Важная продуктовая логика

**Дорога полностью исключена из продуктовой модели.**

Фильтр «Сколько времени на свидание?» — это целевая длительность самих глав сценария: активностей, еды и событий. Движок не использует выбранное время как простой верхний предел: например, при выборе 6 часов он старается собрать сценарий примерно на 5–6 часов и не подменяет его вариантом на 3 часа.

Район используется только для того, чтобы подбирать географически уместные места. Если выбран конкретный район, сценарий собирается внутри него. Если выбрана вся Москва, движок дополнительно предпочитает более цельные комбинации по районам, но не показывает пользователю технический скоринг.

## Что уже работает

- mobile-first интерфейс;
- 3 сценария вместо каталога;
- длительность: 2 / 3 / 4 / 6 часов;
- быстрые бюджеты;
- 5 настроений;
- район Москвы;
- дополнительные пожелания: еда, события, только помещения, без баров;
- подбор актуальных событий на выбранную дату;
- целевой диапазон длительности: длинный фильтр даёт длинный сценарий;
- жёсткий контроль бюджета;
- разные сценарные шаблоны для коротких и длинных свиданий;
- «Показать другие 3» без повторного заполнения формы;
- сохранение последних предпочтений в `localStorage`;
- ссылки на первоисточники мест и событий;
- 3 постерных стиля приглашения: «Терракота», «После полуночи», «Editorial»;
- копирование и Web Share для приглашения;
- PWA manifest + service worker;
- seed-база для мгновенной работы;
- автоматическое обновление данных KudaGo через GitHub Actions.

## Запуск локально

Никакой сборки и npm-зависимостей для самого сайта нет.

```bash
cd 1001-dates
python3 -m http.server 8080
```

Откройте:

```text
http://localhost:8080
```

## Обновление базы

Нужен Node.js 18+.

```bash
node scripts/update-kudago.mjs
```

По умолчанию скрипт запрашивает до 300 популярных мест и до 200 актуальных событий Москвы, нормализует их под модель 1001 Dates и записывает snapshot в:

```text
data/kudago.generated.js
```

Объём можно увеличить:

```bash
KUDAGO_PLACE_PAGES=5 KUDAGO_EVENT_PAGES=4 node scripts/update-kudago.mjs
```

Если API временно недоступен, приложение продолжает работать на `data/seed.js`.

## GitHub Pages

1. Создайте репозиторий `1001-dates`.
2. Загрузите содержимое этой папки в корень репозитория.
3. Откройте **Settings → Pages**.
4. Выберите публикацию из ветки `main`, папка `/ (root)`.
5. После публикации сайт работает без дополнительной сборки.

Все внутренние пути относительные, поэтому проект подходит и для адреса вида:

```text
https://username.github.io/1001-dates/
```


## Обновление существующего репозитория

Если 1001 Dates уже опубликован через GitHub Desktop, замените в локальном репозитории файлы из новой версии, затем сделайте обычный commit и **Push origin**.

В этой версии cache key service worker поднят до `1001-dates-v6`, а регистрация service worker выполняется с `updateViaCache: none`. Это сделано специально, чтобы iPhone не продолжал показывать старый интерфейс после публикации. После первого обновления страницы новая версия должна забрать свежие файлы и удалить старый cache.

## Автоматическое обновление данных

В `.github/workflows/refresh-data.yml` лежит workflow, который обновляет snapshot KudaGo и коммитит изменения в репозиторий.

Он запускается при первом push в `main`, затем ежедневно по расписанию. Также его можно запускать вручную через GitHub Actions.

## Как работает генератор

```text
filters
  ↓
подходящие сценарные шаблоны
  ↓
кандидаты мест / событий
  ↓
проверка даты, целевой длительности и бюджета
  ↓
ranking по настроению, качеству и цельности
  ↓
diversity filter
  ↓
3 разных свидания
```

В базе хранятся не тысячи жёстко прошитых свиданий, а отдельные места и события. Движок собирает их через сценарные шаблоны: «искусство → ужин», «активность → десерт», «ужин → событие», «вид → прогулка» и т. д. Поэтому при росте базы количество возможных комбинаций растёт автоматически.

## Следующий технологический слой

Статический GitHub Pages хорошо подходит для текущей версии без аккаунтов и серверных секретов. Когда понадобятся профили пары, синхронизация между устройствами, настоящие share-ссылки приглашений и персональный ranking, данные пользователя можно вынести в backend/PostgreSQL без изменения основной модели сценариев.
